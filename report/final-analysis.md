## 02　七版 Skill 如何演进

| 版本 | 课程周次 | 主文件行数 | 本版新增或重组 |
| --- | --- | ---: | --- |
| v1 | 第二周 | 61 | 区分编译证据、汇编推演和动态栈观察 |
| v2 | 第三周 | 83 | 加入 mykernel 补丁、QEMU 和定时器证据 |
| v3 | 第四周 | 80 | 重组流程，增加内核启动的 GDB 断点链 |
| v4 | 第五周 | 93 | 对照 i386 的 libc 调用与内联汇编 |
| v5 | 第六周 | 105 | 识别用户态 write，解释返回前条件调度 |
| v6 | 第七周 | 117 | 跟踪 fork，明确 PID 与栈字段的观察时点 |
| v7 | 第八周 | 131 | 对照 ELF 属性、动态入口和初始栈证据 |

v2 到 v3 减少了三行，但新增了启动跟踪。行数只反映主说明文件的长度。功能演进体现在验证步骤更具体，例如看到定时器打印时，还要有任务选择和真正发生切换的证据。观察 fork 时，从 `copy_thread` 入口读取的 PID 也要结合字段赋值时点解释。

每一轮用这一周的快照重新写对应预习题。审阅重点是具体的证据前提：第二周补上栈帧布局适用的 ABI。第四周明确 GDB 断点与正常启动菜单来自不同会话。第七周标出 `thread.sp/ip` 赋值后的数值是否实际读取。

课程原有的技能变化继续保留。本次审阅的批注记录的是回放中的修订，形成时间晚于历史快照。由于七轮题目不同，版本间的效果用下面的同题复测比较。

## 03　同题复测与迁移

两版都收到第八周 ELF 预习材料，同时使用各自归档的规则和参考文件。每项覆盖记 1 分，分数来自本次输出的逐项核对。

| ELF 同题检查 | v1 | v7 |
| --- | --- | --- |
| 给出静态 ELF 的文件入口与 GDB 入口 | 通过 | 通过 |
| 用解释器段解释动态 ELF 的新入口 | 通过 | 通过 |
| 区分已观察的栈指针和待验证的栈布局 | 通过 | 通过 |
| 比较 `DT_NEEDED` 与 `dlopen` 示例 | 遗漏 | 通过 |
| 给出 readelf 和 GDB 的复查命令 | 遗漏 | 通过 |
| 合计 | 3 / 5 | 5 / 5 |

归档的 i386 静态样本两处入口均为 `0x8048d0a`。动态样本的应用入口为 `0x8048350`，GDB 的 `new_ip` 为 `0xb77d90d0`。结合 `PT_INTERP`，可知动态样本先进入解释器。v7 将对应关系落实到 `readelf`、`start_thread` 和动态节的对照步骤，也标出还需从 `new_sp` 转储栈内存的证据缺口。

用第十周 KVM 与容器的教材阅读题复测时，v7 给出 KVM/QEMU 分工、宿主与来宾内核的边界，以及 namespace 和 cgroups 的分工。输出注明教材阅读范围，保留了课程档案中的证据类型。本次没有重跑历史 QEMU 和 GDB 会话。一次同题对照和一个迁移输入只支持这两次观察。

可以复用的做法是把实验见到的现象、源码或 ABI 所解释的机制、需要补采的证据分别写清。以后加入新课程主题时，先核对该主题中最容易被截图或日志误导的结论，再增加有针对性的验收步骤。
